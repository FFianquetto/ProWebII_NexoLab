NexoLab — Aportaciones del equipo (4 integrantes)
Proyecto: ProWebII — Plataforma de gestión de laboratorios, equipo, reservas e incidencias
================================================================================

1) Fernando
   Rol: Base de datos MongoDB + integración con el Backend (API que ya escucha)
   ----------------------------------------------------------------
   - Configuración del cluster MongoDB Atlas (URI, acceso de red, base "nexolab").
   - Diseño del esquema Prisma (8 colecciones): users, subjects, laboratories,
     equipment, reservations, reservation_equipment, incidents, reports.
   - Definición de enums de negocio (roles, estados de lab/equipo/reserva/incidencia).
   - Integración ORM Prisma Client en el backend (conexión, generate, db push).
   - Script de seed (prisma/seed.js): usuarios demo, laboratorios, equipos,
     reservas e incidencias de prueba.
   - Script de inicialización / índices en database/mongo-init.js.
   - Controllers del backend que consumen Prisma para CRUD real contra MongoDB
     (laboratorios, equipos, reservas, incidencias, usuarios, reportes, etc.).
   - Variables de entorno DATABASE_URL, PORT=4000 y endpoint /api/health.
   - Arranque del servidor Express en backend/src/index.js con app.listen(port):
     al correr "npm run dev" la API ya queda escuchando en http://localhost:4000.
   - Documentación de cómo sincronizar e insertar datos (db:generate, db:push, db:seed).

   POR QUÉ CON ESTA PARTE LA APLICACIÓN YA ESCUCHA
   ----------------------------------------------------------------
   El frontend (puerto 2000) no habla con MongoDB directamente: solo llama a la API.
   En el backend se monta Express, se cargan las rutas bajo /api y se ejecuta:

     app.listen(PORT)  →  "NexoLab API escuchando en http://localhost:4000"

   Eso significa que el proceso Node ya está vivo y acepta peticiones HTTP.
   Como Mongo + Prisma ya están integrados (DATABASE_URL, schema, seed, controllers),
   en cuanto el servidor escucha, la aplicación ya puede:
     - responder /api/health,
     - autenticar contra usuarios en Mongo,
     - hacer CRUD real sobre las 8 colecciones.

   Sin este backend escuchando y conectado a Mongo, las pantallas del frontend
   no tendrían de dónde sacar ni guardar datos.
